# 原创性检查规则

> 版本：0.1.0
> 状态：草案（尚未实现）
> 关联任务：T067

---

## 1. 功能定位

Originality Checker（原创性检查器）是参考小说驱动原创写作链路中的安全屏障。它在 AI 生成内容后、内容被写入用户小说文件前执行检查，确保生成内容不侵犯参考小说的原创性。

**核心原则：任何生成内容在写入文件之前，必须通过原创性检查。检查失败的内容不能自动进入下一流程。**

---

## 2. 检查时机

| 检查点 | 时机 | 检查内容 |
|---|---|---|
| Story Bible 生成后 | Reference Creation Profile → Story Bible 后 | 完整原创性扫描（角色名、地名、人物关系、剧情架构） |
| 用户修改 Story Bible 后 | 用户手动编辑后保存前 | 重新扫描修改部分 |
| **章节生成后（关键检查点）** | Daily Writer 每章生成后、写入文件前 | 完整原创性扫描 + 原文片段扫描 |
| 批量生成前 | 多章连续生成前的预检查 | Story Bible + 上下文一致性 |

---

## 3. 检查输入

| 输入项 | 来源 | 说明 |
|---|---|---|
| 待检查内容 | AI 生成的 Story Bible 或章节文本 | 主要检查对象 |
| Reference Creation Profile | `_reference/reference_creation_profile.json` | 用于对比原创性方向 |
| `name_map.json` | 导入时的匿名化映射表 | 检查是否出现原始名称 |
| 参考小说全文（匿名化后） | `_reference/raw_anonymous.txt` | 原文片段相似度对比 |
| Story Bible（已有） | `story-bible.json` | 检查是否与已有设定一致 |
| `originality_rules` | Reference Creation Profile 中的规则字段 | 具体可执行的原创性边界 |

---

## 4. 检查输出

### 4.1 输出格式

```json
{
  "check_id": "uuid",
  "timestamp": "2026-05-24T12:00:00Z",
  "target": "story_bible | chapter",
  "target_id": "novels/demo-project/chapters/ch01.md",
  "overall_result": "PASS | WARN | FAIL",
  "checks": [
    {
      "rule_id": "ORIG-001",
      "rule_name": "原文片段复制检查",
      "result": "PASS | WARN | FAIL",
      "severity": "critical",
      "detail": "未发现超过 15 字词的连续复制",
      "evidence": null
    }
  ],
  "warnings": [],
  "failures": [],
  "action_required": "none | manual_review | block"
}
```

### 4.2 结果等级

| 等级 | 含义 | 动作 |
|---|---|---|
| PASS | 所有检查通过 | 允许继续 |
| WARN | 存在中等风险 | 标记告警，建议人工审查，不阻止流程 |
| FAIL | 存在高风险或严重违规 | **阻止流程**，转入人工确认 |

---

## 5. 检查等级定义

| 严重程度 | 标签 | 触发示例 | 默认动作 |
|---|---|---|---|
| critical | 严重违规 | 直接复制原文片段、搬运角色名 | 阻止生成 |
| high | 高风险 | 人物关系网络高度同构、剧情链条相似 | 阻止生成，要求人工确认 |
| medium | 中等风险 | 风格过度近似、情感基调高度一致 | 标记警告，建议人工审查 |
| low | 低风险 | 使用了相同的流派标签或通用类型描述 | 记录日志，不提醒 |

## 6. 不能复制原文规则

### 6.1 检查方法

| 方法 | 说明 |
|---|---|
| 最长公共子序列（LCS） | 计算待检查内容与参考小说原文的最长公共子序列长度 |
| N-gram 匹配 | 将参考小说原文切分为 N-gram（N=5,10,15），检查待检查内容中是否出现 |
| 滑动窗口相似度 | 以 50 字为窗口滑动，计算每个窗口与参考小说原文的相似度 |

### 6.2 判定规则

| 条件 | 结果 | 严重程度 |
|---|---|---|
| 存在连续 ≥ 15 字词的完全匹配 | FAIL | critical |
| 存在连续 10-14 字词的完全匹配 | FAIL | high |
| 存在连续 5-9 字词的完全匹配 + 相似上下文 | WARN | medium |
| 没有任何 ≥ 5 字词的完全匹配 | PASS | - |

### 6.3 例外

以下情况不视为违规：
- 通用中文表达（如"他点了点头""窗外下着雨"）
- 标点符号和数字组合
- 系统注入的模板文本（如章节标题格式）

## 7. 不能搬运角色名规则

### 7.1 检查方法

对照 `name_map.json` 中的映射表，检查待检查内容中是否出现：

| 名称类型 | 检查方式 |
|---|---|
| 原始角色名 | 精确匹配 + 模糊匹配 |
| 原始角色名变体 | 同音字、形近字、拆字、拼音替换 |
| 外号/昵称 | 对照映射表中的别名列表 |
| 专有名词 | 地名、组织名、特殊物品名、招式名 |

### 7.2 判定规则

| 条件 | 结果 | 严重程度 |
|---|---|---|
| 出现原始角色名（精确匹配） | FAIL | critical |
| 出现角色名变体（同音/形近） | FAIL | critical |
| 出现原始地名/组织名 | FAIL | critical |
| 出现原始专有名词 | FAIL | high |
| 未出现任何已知名称 | PASS | - |

---

## 8. 不能搬运完整剧情桥段规则

### 8.1 检查方法

将参考小说的关键剧情桥段抽象为事件序列模板，与待检查内容的剧情结构进行对比。

| 对比维度 | 方法 |
|---|---|
| 事件类型序列 | 提取两边的"事件类型"序列（如：相遇→冲突→和解→分离），计算序列相似度 |
| 因果关系图 | 构建事件之间的因果关系图，检查图结构同构度 |
| 场景组合模板 | 检查场景的选择和排列是否存在一致模式 |

### 8.2 判定规则

| 条件 | 结果 | 严重程度 |
|---|---|---|
| 连续 3 个以上事件的类型序列与参考小说一致 | FAIL | high |
| 因果关系图结构同构度 > 70% | FAIL | high |
| 场景组合模板高度一致（仅次要参数不同） | WARN | medium |
| 没有明显的剧情桥段相似性 | PASS | - |

---

## 9. 不能简单换皮规则

### 9.1 换皮检测方法

| 检测维度 | 方法 |
|---|---|
| 名称全替换 | 检查是否所有专有名词都被替换但结构不变 |
| 背景全替换 | 检查是否场景设定被替换但事件逻辑不变 |
| 能力体系全替换 | 检查是否力量体系名称被替换但层级和效果不变 |
| 人物关系网络 | 检查人物关系图是否与原作同构（节点数相同、边类型相同） |
| 综合换皮评分 | 多个维度的加权评分 |

### 9.2 判定规则

| 条件 | 结果 | 严重程度 |
|---|---|---|
| 人物关系网络与原作同构（节点数相同 + 边类型匹配度 > 80%） | FAIL | high |
| 事件逻辑链与原作一致（仅替换了事件的外在描述） | FAIL | high |
| 综合换皮评分 > 0.7 | FAIL | high |
| 综合换皮评分 0.4-0.7 | WARN | medium |
| 综合换皮评分 < 0.4 | PASS | - |

## 10. 风格参考和抄袭风险的边界

### 10.1 明确的边界

| 场景 | 属于 | 处理 |
|---|---|---|
| "冷峻克制的叙事基调" | 风格参考（允许） | PASS |
| "使用中短句，节奏干净" | 风格参考（允许） | PASS |
| "对话约占 30%" | 风格参考（允许） | PASS |
| "第 3 章写主角在火车站遇到一个神秘老人" | 具体桥段（禁止） | FAIL |
| "创造一个性格孤僻但内心敏感的主角" | 人物原型（允许） | PASS |
| "创造一个叫 XXX 的孤儿主角，额头有疤，住在楼梯下的储物间" | 具体人物（禁止） | FAIL |

### 10.2 判断原则

- **抽象规律 → 允许。** 如"慢热型叙事""人物共情型钩子"
- **具体内容 → 禁止。** 如"主角在广告公司工作""第 5 章父亲生病"
- **通用表达 → 允许。** 如"他叹了口气""天色渐暗"
- **独特表达 → 禁止。** 如参考小说中独有的比喻、描写方式

## 11. 检查结果如何反馈给 Daily Writer

### 11.1 PASS 时

检查通过，Daily Writer 正常保存章节文件，流程继续。

### 11.2 WARN 时

标记警告但允许继续：
- 在章节文件的元数据中记录警告信息（不写入正文）
- 在 `reports/originality/` 中生成警告报告
- 发送通知给用户（如果有通知机制）

### 11.3 FAIL 时

阻止流程：
1. Daily Writer 不写入章节文件
2. 生成失败报告，包含：
   - 具体违规的类型和位置
   - 违规内容的引用（标注）
   - 修改建议
3. 流程状态标记为 `BLOCKED`
4. 等待用户介入（人工修改或确认重新生成）
